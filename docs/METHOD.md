# Architecture and Training Method

Let the original visual sequence be `X ∈ R^(N×D)`. The generator produces `P ∈ R^(M×N)` with nonnegative entries and unit row sums. Thus, `C = PX` consists of convex combinations of the original tokens. `ratio` is the retention fraction, with `M = max(1,min(N,round(N*ratio)))`; 0.1 retains 10% of the tokens. Python's `round` uses ties-to-even rounding.

Tree and Column project visual features into a smaller hidden space and compute token scores using local convolutions and a scoring network. The scores and a local-detail estimate from the original visual features determine nonempty spatial regions, one per output token. Within each region, a temperature-scaled softmax produces aggregation weights; entries outside that region are masked. Outputs are sorted by their representative tokens' original order. Partitioning, region selection, and representative-token selection are detached discrete operations. Gradients flow through the soft weights and the frozen downstream model; tree splitting itself is not fully differentiable.

The UND generator takes 768-dimensional raw visual features and 2,048-dimensional aligned features. Before-merger experiments fill the aligned-feature input with zeros rather than reading the downstream merger output. Tree additionally uses question embeddings from the frozen LLM and learns visual–question relevance. This is decoder-dependent task training, not a decoder-free objective. Column uses column-first two-dimensional partitioning. The corresponding implementations are `SpatialGenerator('quadtree_question')` and `SpatialGenerator('col_adaptive')`.

The UND before-merger path is `encoder -> P @ raw -> official merger -> original LLM`. In the after-merger path, the generator receives raw and projected features, compresses the projected features, and passes them to the original LLM. These insertion points are distinct and their trained weights are not interchangeable.

For native Qwen3-VL-8B, the generator receives 4,096-dimensional post-merger features and uses a default hidden width of 96. The same P compresses the final visual features and all three DeepStack branches. Representative tokens retain their original MRoPE positions; question and answer positions retain their original indices. The visual encoder and merger have already run, so compression at this point does not reduce their computation. `StableColumn` is a separate architectural variant with fixed detail-based partition allocation and trainable within-region soft weights.

For training, the uncompressed teacher first generates a greedy response `y`. Teacher and student are evaluated on the shared prefix `prompt + y[:-1]`, and their full-vocabulary next-token distributions are compared:

`L = mean_t sum_v p_teacher(v|prefix_t) log(p_teacher(v|prefix_t)/p_student(v|prefix_t))`.

Gold answers are used only for development and evaluation. Training uses no gold cross-entropy, and neither answers nor KV states are carried between independent questions. All backbone parameters are frozen. The student's decoder forward pass must still track gradients so that the loss can update P; wrapping it in `no_grad` would sever that path.

Defaults are AdamW with zero weight decay, 10% linear warmup, and cosine decay to 0.1 of the initial learning rate. The default clipping threshold is 5; UND templates retain candidate configurations with a threshold of 1. Logs record the pre-clipping gradient norm and clipping multiplier. Full training starts from a fresh initialization with a fixed seed rather than continuing a pilot checkpoint. A candidate must reduce development KL by at least 5% and improve the development macro score by at least 0.25 percentage points, with the original native implementation's teacher-saturation exception retained. Among eligible epochs, selection maximizes development macro score and then minimizes KL. If no epoch is eligible, the initial checkpoint is locked and the negative result is retained.

The KL objective draws on MetaCompress's prediction-preservation idea. The spatial generator, shared-response-prefix implementation, and default omission of row entropy should be distinguished from the original paper. The implementations in `vqa/meta_compress.py` and `vqa/decoder_dependent_loss.py` are retained for comparison; the complete repository should not be described as the original MetaCompress architecture. References are provided in `references.bib`.
